> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Start with `docs/HANDOFF.md`. Revision 2 incorporates every Critical and Important finding of `docs/specs/2026-10-09-setu-review.md`; where this plan and the spec disagree, the spec (revision 2) wins and the disagreement is a ledger ruling.

**Goal:** One `setu` binary whose `serve` role (control plane with embedded UI) and `agent` role (per-server, via a typed privileged helper) provision a single-binary app from a manifest as a hardened systemd unit with its own Postgres database and Caddy TLS route, back it up on a schedule, update it with database-restoring rollback, and delete it, on one or many Ubuntu 24.04 servers, proven by an end-to-end test that also provisions real Vyasa 0.2.0.

**Architecture:** Cargo workspace: `common` (config, sealing, ids, domain, errors), `manifest` (pure validator, env resolution), `proto` (commands, results, heartbeat), `db` (sqlx repos, migrations, leases), `jobs` (step state machines over `AgentClient`, runner with scheduler), `agent` (lib: runtime, helper, adapters, loop, install), `api` (axum control plane, embedded UI, **the `setu` binary** mounting `serve`, `agent`, `helper`, `migrate`, `operator`, `backup`), `apps/hello` (test app). Control plane ↔ agent only through long-polled, idempotent, expiring commands.

**Tech Stack (pinned to Vyasa's current versions):** tokio 1, axum 0.8, tower 0.5, tower-http 0.6, sqlx 0.9, serde 1, serde_json 1, toml 1, thiserror 2, anyhow 1, tracing 0.1, tracing-subscriber 0.3, utoipa 6, argon2 0.6, chacha20poly1305 0.11, sha2 0.11, rand 0.8, base64 0.23, hex 0.4, ulid 1, chrono 0.4, clap 4, reqwest 0.13 (rustls, no default features), config 0.15, rust-embed 8, async-trait 0.1, futures 0.3, semver 1, url 2, tempfile 3, serial_test 3, tar 0.4, flate2 1, zstd 0.13, idna 1, nix 0.29 (user, fs). Sessions: our own `sessions` table and a small store (`tower-sessions-sqlx-store` 0.15 depends on sqlx ^0.8, verified 2026-10-09, so it is out). reqwest with `rustls-tls-ring`-style features (ring provider) so the musl build needs no cmake. Caddy socket client: `hyper` 1 + `hyper-util` + `http-body-util` over `tokio::net::UnixStream`. UI: Vite, React 19, TypeScript, TanStack Router/Query/Table, Tailwind 4, shadcn/ui, vitest, openapi-typescript. ## Review Focus

1. Helper given a `--site` of `../etc` or a site dir whose `env` is a symlink — must refuse before writing — Task 10b tests `helper_rejects_bad_site_id`, `helper_refuses_symlinked_env`, `helper_refuses_symlinked_parent`.
2. A hosted process trying `curl --unix-socket /run/caddy/admin.sock` or `localhost:2019` — must fail (socket group, TCP off) — Task 11 e2e assertions `caddy_tcp_admin_closed`, `site_user_cannot_open_admin_socket`.
3. Update to a version whose archive contains `../x` or a setuid binary — `install` must fail before `stop` — Task 10b `install_rejects_traversal_and_special_bits`, Task 6 `bad_archive_update_never_stops_the_site`.
4. Control plane killed between `stop` and `switch_version` of an update — on restart the job resumes from the cursor and the site ends `running` on V — Task 9 `update_resumes_after_runner_restart`.
5. Agent returns with a new `boot_id` while a command is `delivered` — requeued at once and executed exactly once (dedupe) — Task 8 `new_boot_id_requeues_delivered_commands`, Task 10d `duplicate_command_id_returns_cached_result`.
