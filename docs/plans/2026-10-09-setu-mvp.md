**Goal:** One `setu` binary whose `serve` role (control plane with embedded UI) and `agent` role (per-server, via a typed privileged helper) provision a single-binary app from a manifest as a hardened systemd unit with its own Postgres database and Caddy TLS route, back it up on a schedule, update it with database-replacing rollback, and delete it, on one or many Ubuntu 24.04 servers, proven by an end-to-end test that also provisions real Vyasa 0.2.0.

**Architecture:** Cargo workspace: `common` (config, sealing, ids, domain, errors, `TestDb`), `manifest` (pure validator, env resolution and merge), `proto` (commands, results, heartbeat), `db` (sqlx repos incl. sessions, migrations, leases, command queue), `jobs` (step state machines over `AgentClient`, runner with leases, scheduler), `agent` (lib: runtime, helper, adapters, reconcile, loop, install), `api` (axum control plane, embedded UI, **the `setu` binary** mounting `serve`, `agent`, `helper`, `migrate`, `operator`, `backup`), `apps/hello` (test app). Control plane ↔ agent only through long-polled, idempotent, expiring, deduplicated commands.

**Tech Stack (pinned to Vyasa's current versions):** tokio 1, axum 0.8, tower 0.5, tower-http 0.6, hyper 1 + hyper-util + http-body-util (unix-socket client), sqlx 0.9, serde 1, serde_json 1, toml 1, thiserror 2, anyhow 1, tracing 0.1, tracing-subscriber 0.3, utoipa 6, argon2 0.6, chacha20poly1305 0.11, sha2 0.11, rand 0.8 (check `rand_core` compatibility with argon2 0.6's `password-hash` at Task 0; if they conflict use `getrandom` directly for salts and ledger it), base64 0.23, hex 0.4, ulid 1, chrono 0.4, clap 4, reqwest 0.13 (rustls with the `ring` provider, no default features), config 0.15, rust-embed 8, async-trait 0.1, futures 0.3, semver 1, url 2, tempfile 3, serial_test 3, tar 0.4, zstd 0.13, flate2 1, idna 1, nix 0.29 (user, fs). Sessions: own table. UI: Vite, React 19, TypeScript, TanStack Router/Query/Table, Tailwind 4, shadcn/ui, vitest, openapi-typescript. - Repo `/home/gopal/Desktop/wp/setu`, remote `origin` = github.com/vyasa-cms/setu (private; never public without the owner). Feature branches in worktrees `../setu-work-<n>`; PRs against `origin/main`. No Claude co-author trailers or tool lines in commits or PRs.

- Names: ULID ids; `short_id` = 8 lowercase `[a-z0-9]` chars, unique per server; user `setu-site-<short>`, unit `setu-site@<short>.service`, db and role `site_<short>`.
- Validation regexes (manifest validator **and** helper): short id `^[a-z0-9]{8}$`; version `^[0-9A-Za-z.+-]{1,64}$`; exec `^[A-Za-z0-9._-]+(/[A-Za-z0-9._-]+)*$` and no `..` component; dir `^[a-z][a-z0-9-]{0,31}$`; env name `^[A-Z][A-Z0-9_]*$`; args and env values: no control characters.
- Secrets: KeyVault scheme (`v1:` sealed, `plain:` unsealed, SHA-256 key derivation with label `setu-seal-v1`); manual `Debug` on every secret-bearing struct (`EnvVar`, `CreateDatabase`, `WriteEnv`, `JoinRequest`, `JoinResponse`, `Config`, agent config); agent-side log redaction; `agent_commands` secret fields nulled on completion, cancel, expiry and prune; passwords never on argv (`\set` on psql stdin, `PGPASSWORD` env for `pg_dump`).
- Errors: `{ "error": { "code", "message" } }`; codes `validation` 400, `unauthorized` 401, `forbidden` 403, `not_found` 404, `conflict` 409, `agent_unreachable` 502, `internal` 500 (fixed message, detail logged).
- UI codegen from the repo's `openapi.json` only.
- Every task ends green: `cargo fmt --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && bash scripts/test.sh` and, for UI tasks, `pnpm -C ui lint && pnpm -C ui typecheck && pnpm -C ui test`. ## Review Focus

1. Helper given a bad `--site`, a `version` of `../x`, an `exec` containing a newline or `%`, or a site dir whose `env` is a symlink — must refuse before writing — Task 10b tests `helper_rejects_bad_site_id`, `helper_rejects_bad_version`, `write_unit_rejects_newline_percent_and_dollar`, `helper_refuses_symlinked_env`, `helper_refuses_symlinked_parent`, `helper_refuses_root_flag_under_sudo`.
2. A hosted process trying TCP 2019 or the admin socket, or binding `0.0.0.0` in the port range — must fail — Task 11 assertions `caddy_tcp_admin_closed`, `site_user_cannot_open_admin_socket`, `public_bind_refused_by_firewall`.
3. Update to an archive with `../x` or a setuid file, or whose new version migrates and then fails health — `install` fails before `stop`; rollback replaces the database — Task 6 `bad_archive_update_never_stops_the_site`, `update_rolls_back_with_restore_when_health_fails`; Task 11 assertion `rollback_restores_database`.
4. Control plane killed between `stop` and `switch_version` — job resumes from the cursor, site ends `running` on V — Task 9 `update_resumes_after_runner_restart`.
5. Agent exits after executing a command and before posting — on restart the redelivered command returns the cached result and the helper ran once — Task 10d `duplicate_command_id_returns_cached_result_without_reexecuting`, Task 11 assertion `agent_exit_mid_provision_recovers`.
