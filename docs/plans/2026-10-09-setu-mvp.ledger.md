# Setu MVP (0.1.0) ledger

Branch `mvp`. The spec (`docs/specs/2026-10-09-setu-design.md`) is the
authority; this ledger records every ruling (spec/plan conflicts and
judgment calls) plus deferred minors. Final gate outputs at the bottom.

## Rulings

- R1 (Task 0): licence `AGPL-3.0-only` in `Cargo.toml` as the plan says;
  the owner deferred the final decision (spec §12). Cost if wrong: one
  `sed` + `deny.toml` touch before any push.
- R2 (Task 1): `test.sh` places `"$@"` before `--`
  (`cargo test --workspace "$@" -- --test-threads=4`), not the plan's
  literal order, which would feed `-p` to the test binary.
- R3 (Task 1): placeholder migration numbered `0000_*` so Task 5's
  `0001_init.sql` lands cleanly (placeholder deleted on arrival).
- R4 (Task 2): added `url = "2"` workspace dep (plan Task 0 pins lacked
  it; `public_url: Url` needs it).
- R5 (Task 2): config env uses `.prefix_separator("_")` — the plan's
  bare `.separator("__")` requires `SETU__FOO` and ignores `SETU_FOO`.
- R6 (Task 2): `seal.rs #![allow(deprecated)]` for generic-array 0.14
  via chacha20poly1305 0.10 (staying per plan); revisit on upgrade.
  `seal()` keeps the plan's infallible signature with a documented
  infallibility justification for its two `expect`s.
- R7 (Task 3): vyasa corpus sha is the empty-string placeholder
  (`e3b0c44…`); replace with real 0.2.0 checksums when known.
- R8 (Task 3): `resolve_env` takes `&mut ResolveInput` (rng mutation);
  the plan's `&` signature is impossible.
- R9 (Task 3): `Prompt` accepts `label` or `prompt=` (alias kept).
- R10 (Task 4): field-type gaps filled (`port: u16`, `timeout_s: u64`,
  `cpu_seconds: f64`, `pid: Option<u32>`, …).
- R11 (Task 5): migrate advisory-lock key is 64-bit
  (`sha256("setu-migrate")` head, `-4436319754632771127`), not the
  plan's 16-bit `0x5e7u`.
- R12 (Task 5): `join()` marks the server `online` immediately;
  `online()` = heartbeat within 60 s, `offline` computed at read time.
- R13 (Task 5): `agent_commands` repo added (plan file list omits it,
  interfaces require it); `requeue_stale` is global, not per-server —
  the runner calls it once globally.
- R14 (Task 6): manifest JSON round-trip via `serde_json::Value`
  intermediate (`toml::Value` cannot hold JSON `null`).
- R15 (Task 6): update strategy `command` runs as `Restart` + `Health`
  (no generic exec in proto; agent detail deferred, still open).
- R16 (Task 6): timeout-retry policy is retry-exactly-once on `Timeout`
  for every agent call (shared helper).
- R17 (Task 7): `TestServer` lives in `setu_api::testing`, not testkit
  (testkit→api would be a dependency cycle).
- R18 (Task 7): custom `PgSessionStore` over the `sessions` table —
  `tower-sessions-sqlx-store` pins sqlx 0.8 ≠ our 0.9. Swap when
  upstream supports 0.9.
- R19 (Task 7): new `ErrorCode::RateLimited` (`rate_limited`/429); the
  spec's code list has no 429.
- R20 (Task 7): SSRF guard checks ALL resolved IPs + no redirects +
  10 s + 1 MiB cap; residual DNS-flip TOCTOU accepted and documented
  (pinning to IP breaks https cert verification).
- R21 (Task 7): session cookie `Secure` follows `public_url` scheme.
- R22 (Task 8): long-poll is 100 ms DB polling (default/cap 30 s), not
  the plan's Notify map — fine at MVP fleet sizes; see ledger note.
- R23 (Task 8): `requeue_stale` no longer bumps `attempts` (only
  `next_for` counts deliveries).
- R24 (Task 8): per-server 600 polls/min limiter on agent commands.
- R25 (Task 8): repeat result post is an idempotent no-op (first wins);
  foreign-site metrics in heartbeats are ignored (204, not 400).
- R26 (Task 9): `TestServer` spawns the real `Runner` (concurrency 4)
  over `FakeAgent`, so API tests provision for real.
- R27 (Task 9): added `stop_site`/`start_site` job kinds (plan lists
  the endpoints; the runner needed the dispatch).
- R28 (Task 9): DELETE returns `{job}` wrapper (row is gone at finish).
- R29 (Task 9): backup/restore/delete build the agent spec WITHOUT env
  re-resolution (`build_spec`): those jobs carry no prompts, and
  re-resolving would fail on prompt manifests and mint throwaway
  secrets.
- R30 (Task 10): sudoers cannot pin per-site units (visudo rejects
  wildcards in args) — ALL root ops go through `sudo setu helper …`
  (`helper *` + in-helper allowlists). The spec §4 fixed-list is
  superseded; AGENT.md/SECURITY.md describe the actual model.
- R31 (Task 10): `tar`+`flate2` over shell tar; disk-free via `df`,
  load via `/proc`; apt installs missing-only, never upgrades.
- R32 (Task 10): recorded version = running version (install never
  touches `current`; only `SwitchVersion` moves it).
- R33 (Task 10): usernames are `setu-site-<short8>` (32-char shadow
  cap), lowercased everywhere (builders + api env spec).
- R34 (Task 11): e2e builds debug binaries; all versions share bytes
  (version string + env distinguish them).
- R35 (Task 11, e2e-found): control-plane `data_dir` default is
  `/srv/setu` (not `/var/lib/setu`): site dirs are addressed ON AGENTS
  as `<data_dir>/sites/<id>` and must land in the helper allowlist.
- R36 (Task 11, e2e-found): Caddy `routes` is index-addressed —
  `@id`-in-path is 500; upsert = list + PATCH whole array (PUT is
  create-only on 2.6.2), ours first; delete by index. Verified against
  real Caddy 2.6.2 AND 2.11.7 (probe containers, removed after).
- R37 (Task 11, e2e-found): install converges Caddy (`/load` unless a
  `setu-` route exists — never wipe live); `enable --now` for
  postgres/caddy (policy-rc.d containers); agent starts only AFTER
  join (no token crash-loop); `SETU_AGENT_CADDY_INTERNAL_TLS=off`
  for e2e only.
- R38 (Task 11, e2e-found): backup leaves are `setu:postgres/0770`
  (setgid backups root from install + `setu ∈ postgres` group) so
  `pg_dump` can write; leaf mode asserted in unit test.
- R39 (update, e2e-found): update reconciles env — `value`/`from`
  refresh, `generate`/`prompt`/`postgres_url` keep stored values
  (fresh `build_site` mints passwords that would desync DB auth);
  written pre-stop with best-effort restore on failure; `once`
  cleanup mirrored post-health; rollback restores the old file first.
- R40 (Task 12): file-based TanStack routes per Vyasa; generated
  types checked in as `.d.ts`; `build.rs` warns (not fails) without
  `ui/dist` + `cfg(setu_ui)` switch; `sites.$id` overview-only until
  Task 13; `jobs.$id` minimal log tail until Task 13.
- R41 (Task 12/13): env Reveal arms an editor for a NEW value (secrets
  are never returned as plaintext); no usage endpoint — Limits shows

- R42 (Task 13): destructive actions confirm naming the target
  (delete types the name); update added a confirm for consistency.
- R43 (Task 14): `hostname` crate for the local-server default name;
  `SETU_RELEASE_BASE_URL` override for tests; musl via `cross` for
  arm64 (public-only guard for the private repo).
- R44 (Task 14): `POST /setup` is atomic under a transaction-scoped
  advisory lock (`sha256("setu-setup")` head) — sequential

- R45 (Task 14): `install.sh --no-start` enables without starting;
  re-runs reuse `secret_key` + db password from the existing toml

## Deferred / known gaps (not 0.1.0 blockers)

- D1: site data dirs are `setu`-owned while apps run as their site
  user — apps that WRITE (Vyasa media uploads) hit EACCES. Needs a
  chown-to-site-user step in install (helper-covered). E2E does not
  cover app writes (hello is read-only).
- D2: update strategy `command` runs as Restart+Health (R15) — the
  agent-side exec detail is still open.
- D3: `PgSessionStore` custom until upstream sqlx-0.9 support (R18).
- D4: DNS-flip SSRF residual (R20); long-poll polling cost (R22).
- D5: dump-file read for phase-2 S3 upload relies on `setu ∈ postgres`
  group + pg_dump's file mode; revisit in phase 2.
- D6: concurrent xed — installer re-run with an UNPARSEABLE existing
  toml fails loudly (by design, operator moves it aside).
- D7: `has_value: true` is unconditional in env GET; offline-at-create
  is `validation` (400) not `agent_unreachable`; `test.sh`/`test-pg.sh`
  two-worktree same-name race (one-heavy-job rule covers it).
